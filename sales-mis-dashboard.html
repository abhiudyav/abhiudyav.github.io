Sales MIS Dashboard

Completed ExcelMISDashboardData Analysis

A single-workbook, fully formula-driven MIS dashboard over 1,039 Australian retail order lines (Feb 2013 – Feb 2017) — seven live filters, 8 KPI cards, 6 native Excel charts, three ranking tables, and an auto-generated insights panel. No PivotTables, slicers or macros.

01Overview

This is a single .xlsx workbook designed to be handed to someone who has never opened the file before: they open the DASHBOARD tab, pick filters from seven dropdowns, and every KPI, chart, ranking table and insight sentence recalculates instantly. There's nothing to refresh and nothing hidden behind a macro — every number on the sheet is a plain Excel formula that can be clicked on and traced.

Screenshot taken directly from the workbook (filters set to "All").

02Business Problem

Retail order data — order lines, customers, products, salespeople, discounts and shipping — is easy to collect and hard to read. Someone reviewing performance needs to slice it by year, region, category, segment or salesperson without waiting on a new pivot or a new report each time, and needs to trust the numbers without re-deriving them by hand. The brief here was to turn ~1,000 raw order lines into a dashboard a non-technical manager could drive themselves.

03Solution

Rather than PivotTables + Slicers + a VBA refresh macro, the dashboard is built on live SUMPRODUCT / INDEX​/MATCH formulas driven by simple dropdown cells. Functionally it behaves the same way for the end user — change a filter and everything updates immediately — but it's more robust when a workbook is generated programmatically, and every calculation stays auditable on a dedicated calculation sheet rather than living inside opaque pivot cache objects.

Design decision, stated plainly: the workbook's own README documents this trade-off directly — formulas over PivotTables/Slicers/VBA — as a deliberate choice, not an oversight.

04Data Processing

The workbook is organized into six sheets, each with one job:

SheetRole
DASHBOARDFilters, KPI cards, charts, rankings, insights, data quality panel
DATAClean Excel Table (tblData), one row per order line, with computed Year/Quarter/Month/Region/Cost/Profit/Margin columns
CALCHidden calculation engine — pre-aggregated tables by month, category, region, segment, salesperson, product and customer
LISTSHidden source lists powering the seven filter dropdowns
RAW_DATAUntouched copy of the original order data, kept for audit/traceability
READMEUser guide: how to use it, key definitions, and data quality notes

New orders are added by pasting rows below the last row of tblData — the table auto-expands and every formula, chart and KPI includes the new rows automatically.

05Dashboard

Seven cascading filters (Year, Quarter, Month, Category, Region, Segment, Salesperson), each backed by a Data Validation dropdown list — leaving a filter on "All" includes every value for that dimension. Below the filters: 8 KPI cards, a trend + category chart row, a region + segment chart row, and two ranking charts, followed by three ranking tables and an auto-generated insights panel.

08Excel Techniques Used

Actually used, verified in the file:

  • SUMPRODUCT — the core multi-criteria aggregation engine (1,044 uses)
  • INDEX / MATCH — rankings and lookups (81 uses each)
  • LARGE — Top-N ranking logic
  • IF / IFERROR / OR — conditional and error-safe logic throughout
  • COUNTIF / COUNTIFS / COUNTBLANK — the data quality checks
  • TEXT / DATE / YEAR / MONTH — date handling and formatting
  • Native Excel Table (tblData) with structured references
  • Data Validation dropdown lists (7 filters, list-type)
  • Native Excel charts: 1 line, 4 bar/column, 1 pie

Deliberately not used:

  • No PivotTables or Slicers — replaced by the SUMPRODUCT/CALC-sheet engine above
  • No VBA / macros — the workbook is 100% formula-driven
  • No actual Conditional Formatting rules — the ✓/⚠ data quality indicators are plain IF formulas producing text, not CF rules
  • No VLOOKUP or XLOOKUP — INDEX/MATCH was used instead throughout

10Output

One self-contained .xlsx file. No external data connections, no add-ins, no dependencies — it opens and works in any current version of Excel.

11What I Learned

  • How to design a calculation layer (the CALC sheet) that stays fully auditable instead of hiding aggregation logic inside PivotTable caches.
  • How to make a data quality check visible to a non-technical user (the ✓/⚠ panel) instead of leaving bad data to surface only when a total looks wrong.
  • Why documenting definitions (what counts as "Sales", what "Region" means here) inside the workbook itself matters as much as the calculations — a README sheet the user actually has to open.

12Future Improvements
