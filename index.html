Sales MIS Dashboard

A single-workbook, fully formula-driven MIS dashboard over 1,039 Australian retail order lines (Feb 2013 – Feb 2017) — seven live filters, 8 KPI cards, 6 native Excel charts, three ranking tables, and an auto-generated insights panel. No PivotTables, slicers or macros.

Overview

This is a single .xlsx workbook designed to be handed to someone who has never opened the file before: they pick filters from seven dropdowns, and every KPI, chart, ranking table and insight sentence recalculates instantly. Nothing to refresh, nothing hidden behind a macro — every number is a plain Excel formula that can be traced.

Screenshot taken directly from the workbook (filters set to "All").

Business Problem

Order data is easy to collect and hard to read. Someone reviewing performance needs to slice it by year, region, category, segment or salesperson without waiting on a new pivot each time, and needs to trust the numbers without re-deriving them by hand.

Solution

Rather than PivotTables + Slicers + a VBA refresh macro, the dashboard uses live SUMPRODUCT / INDEX/MATCH formulas driven by dropdown cells. It behaves the same way for the end user — change a filter, everything updates — but every calculation stays auditable on a dedicated CALC sheet rather than living inside opaque pivot cache objects.

Design decision, stated plainly: the workbook's own README documents this trade-off — formulas over PivotTables/Slicers/VBA — as a deliberate choice, not an oversight.

Excel Techniques Used

Actually used, verified in the file:

  • SUMPRODUCT — core aggregation engine (1,044 uses)
  • INDEX/MATCH — rankings/lookups (81 uses each)
  • LARGE, IFERROR, COUNTIF(S), COUNTBLANK
  • Native Excel Table + 7 Data Validation dropdown filters
  • 6 native charts: 1 line, 4 bar/column, 1 pie

Deliberately not used:

  • No PivotTables/Slicers — replaced by the SUMPRODUCT engine
  • No VBA/macros — 100% formula-driven
  • No actual Conditional Formatting rules — ✓/⚠ indicators are IF-formula text
  • No VLOOKUP/XLOOKUP in this file — INDEX/MATCH used instead

What I Learned & Future Improvements

  • How to build a calculation layer that stays auditable instead of hiding logic in pivot caches.
  • Why a visible data-quality check (the ✓/⚠ panel) matters more than a total that just "looks right".
  • Next: a Power BI version of the same model; a rolling 12-month YoY view; automated de-duplication of the 4 flagged duplicate Order No values.

MIS Automation (Python)

A modular pipeline that takes a raw CSV/XLSX and does the work of an MIS Executive: profiling, cleaning with a full audit trail, KPI calculation, pivots with native Excel charts, optional AI-generated insights, read-only SQL analysis, and a Power BI-ready export — wrapped into one professional Excel report.

Overview

A CLI (app.py) and a Streamlit UI both call the same core/pipeline.py orchestrator, so the two interfaces can never silently diverge. Run against the bundled sample dataset (510 rows), it produces a 23-sheet Excel report plus a set of CSV exports.

Cover sheet of the actual generated report, run against the bundled sample dataset.

Problem & Solution

Turning a raw export into an MIS report is a manual, repeatable-but-repeated chore: check for missing/duplicate data, clean it consistently, compute the same KPIs, build the same pivots, write it up — every month, by hand. This automates it end-to-end while keeping every step auditable, so a human reviewer can still see exactly what changed and why.

CSV/XLSX→ FileLoader→ Profiler→ Cleaner→ Transformer→ KPI Engine
Pivots + Charts→ AI Insights (opt.)→ SQL (opt.)→ Power BI Export (opt.)→ Excel Report→ Quality Control

Technologies

Python 3pandas openpyxlxlsxwriter SQLAlchemy / SQLiteClaude API Streamlitpytest

Automation & Business Value

  • KPIs/pivots/DAX measures only generate when their source columns actually exist — a missing measure says so, never a fabricated number.
  • SQL is read-only by default, enforced by both generation rules and a keyword filter (blocks DROP/DELETE/TRUNCATE/UPDATE/ALTER/INSERT).
  • No .pbix is created (Power BI isn't available headlessly) — instead: Power BI-ready CSVs, a data dictionary, and suggested DAX measures.
  • Verified on a 150,000-row synthetic dataset: full pipeline runs in ~13 seconds.
  • 44 automated tests; an independent Quality Control pass re-derives totals itself rather than trusting each engine's own math.

What I Learned & Future Improvements

  • Column-name heuristics need tokenization — an identifier hint like "no" was matching inside words like "Notes" via substring matching; fixed with a camelCase-aware tokenizer + regression test.
  • An AI layer is safer when structurally prevented from computing numbers itself — it only ever receives pre-computed figures to interpret.
  • Next: wire this pipeline into the n8n workflow below so reports run and get delivered automatically; streaming ingestion for 500k+ row files.

AI-Powered MIS Executive Automation

An email-to-Excel workflow: someone emails a spreadsheet plus an instruction, the workflow works out what's being asked, does it when confident, asks a clarifying question when it isn't, and emails the finished workbook back.

ℹ Source of this write-up: this description comes from my resume. The n8n workflow export, screenshots and sample runs haven't been added yet — node-by-node detail and output screenshots are intentionally not shown until the actual file is committed.

Overview & Problem

The workflow monitors Gmail for incoming emails with Excel/CSV attachments, validates and extracts them, and uses a Python/FastAPI service to inspect the workbook structure so the Claude API can reason over the real spreadsheet content together with the sender's instructions — instead of the instructions alone. This removes the manual open → interpret → edit → reply loop that routine spreadsheet requests usually need.

Solution & Workflow Architecture

Stages are taken from the resume description — this shows the logical flow, not individual n8n node names.

Gmail: email + Excel/CSV attachment→ Validate + extract→ FastAPI: inspect workbook
Claude API: decision + confidence score→ Confidence check
Low confidence → clarification email
Clear request → FastAPI processing→ Job ID / filename / row counts→ Workbook emailed back

AI Integration

The Claude API receives the workbook structure and content plus the email instructions and returns a structured JSON response: decision, confidence score, task, reason, required columns, requested operations. That response drives the clarify-vs-process branch — the AI decides, the FastAPI pipeline carries out the actual Excel changes.
