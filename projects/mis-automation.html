MIS Automation (Python)

Completed — 9 of 9 phases delivered PythonExcelAutomationData Processing

A modular pipeline that takes a raw CSV or Excel file and does the work of an MIS Executive: profiling, cleaning with a full audit trail, KPI calculation, pivot tables with native Excel charts, optional AI-generated insights, read-only SQL analysis, and a Power BI-ready export — wrapped in one professional Excel report.

01Overview

The project is a Python package (core/ + ai/) with two front ends — a CLI (app.py) and a Streamlit UI (streamlit_app.py) — that both call the same core/pipeline.py orchestrator, so the two interfaces can never silently produce different results. Run against the bundled sample dataset (510 rows), it produces a 23-sheet Excel report plus a set of CSV exports.

Cover sheet of the actual generated report, run against the bundled sample dataset.

02Problem

Turning a raw export into an MIS report is normally a manual, repeatable-but-repeated chore: check for missing/duplicate data, clean it consistently, compute the same handful of KPIs, build the same pivots and charts, and write it all into a report — every single month, by hand. This project automates that chore end-to-end while keeping every step auditable, so a human reviewer can still see exactly what was changed and why.

03Solution

A 9-phase pipeline (see BUILD_PLAN.md in the repo) where each stage has one responsibility and hands off a well-defined result to the next:

Input (CSV/XLSX)→ FileLoader→ Profiler→ Cleaner→ Transformer→ Analyzer + KPI Engine
Pivot + Chart Engine→ AI Insights (optional)→ SQL Engine (optional)→ Power BI Export (optional)→ Excel Report→ Quality Control

07Data Processing

Column typing is evidence-based, not name-based — a column named "Revenue" is only classed as numeric if its values actually parse as numeric at a ≥85% hit rate. Cleaning never silently destroys data: the untouched raw dataframe is always kept alongside the cleaned one and a structured log (column, issue, rows affected, action, before/after, reason). Duplicates and outliers are flagged, never auto-removed, unless explicitly opted into via --drop-duplicates.

08Automation

  • KPIs, pivots and DAX measures are only generated when their source columns actually exist — a missing measure returns "Not available from the supplied data," never a fabricated number.
  • SQL is read-only by default, enforced both by never generating destructive statements and by a keyword filter that rejects DROP/DELETE/TRUNCATE/UPDATE/ALTER/INSERT.
  • No .pbix file is ever created — Power BI Desktop/Service isn't available headlessly, so the pipeline exports Power BI-ready CSVs, a data dictionary and suggested DAX measures instead, and says so explicitly rather than pretending otherwise.
  • Verified against a 150,000-row synthetic dataset: full pipeline runs in ~13 seconds, producing a 3.5MB report.

09Reporting

The generated workbook has 23 sheets: Executive Summary, KPI Summary, Data Quality, Cleaning Log, one sheet per pivot (each with its native chart), Trend Analysis, Anomalies, AI Insights, SQL Analysis, Power BI Notes, Raw/Cleaned/Transformed Data, and Methodology.

KPI Summary sheet — actual output from the sample run (Revenue 3,365,672.95 total, 510 records).

10Output

Per source file: one MIS Excel report, raw/cleaned/transformed CSVs, a cleaning log (CSV + JSON), a Power BI fact table + one dimension CSV per low-cardinality categorical column, a data dictionary, and a DAX measures text file.

11Business Value

  • Reduces the repetitive part of monthly MIS reporting to a single command.
  • Standardises cleaning and KPI logic so two runs of the same data produce the same numbers.
  • Keeps a full audit trail (JSONL) of every automated decision, for review rather than blind trust.
  • Degrades gracefully — AI insights, SQL and Power BI export are all optional and the pipeline runs fully without them if a key or feature is disabled.

No invented percentage improvements are claimed here — these are the properties the code and its 44 passing tests actually demonstrate.

12What I Learned

  • Column-name heuristics are dangerous without tokenization — an identifier hint like "no" was originally matching inside ordinary words like "Notes" via substring matching. Fixed with a camelCase-aware tokenizer and covered by a regression test.
  • An AI layer is safer when it's structurally prevented from computing numbers itself — it only ever receives pre-computed KPI/trend/anomaly figures, never raw data.
  • An independent Quality Control pass that re-derives totals itself (rather than trusting each engine's own math) catches bugs that a self-check inside the same engine would miss.

13Future Improvements

  • Wire this pipeline into a scheduled n8n workflow (see the separate n8n project) so reports run and get delivered automatically instead of via CLI/Streamlit.
  • True out-of-core/streaming ingestion for 500k+ row files (currently read fully into memory).
  • Direct Power BI Service / workspace publishing once available in a non-headless environment.
